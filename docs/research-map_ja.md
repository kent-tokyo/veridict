# リサーチマップ

[English](research-map.md) | 日本語

この文書は未実装の候補を記録するもので、実装予定表ではありません。現在のソースツリーの仕様は
[`metrics_ja.md`](metrics_ja.md)、製品の責任範囲と開発の優先順位は
[プロダクトの目的と範囲](product-scope_ja.md)を参照してください。

実装済みの判定の正しさを、以下の機能候補より優先します。誤った `pass`、非有限な計算結果、
退化した信頼区間への対処は信頼性の修正として扱い、任意の研究上の精緻化とは分けます。

着手には、具体的な利用場面、明確な統計的主張、適切な較正試験、ライセンス上問題のない実装経路が
必要です。それまでは現在の保守的な挙動を維持します。

## 数値メトリクス

| 候補 | 保留理由 | 着手条件 |
|---|---|---|
| `quantile-diff` のBCa | 標本分位点は非平滑で、現在の`p95`較正では被覆率が改善しない | 広い較正条件で再現可能な改善がある |
| 分位点の `power`、`matrix`、`plan` | 分位点分散には密度または分布の仮定が必要 | その仮定を宣言できる高分位点レイテンシ用途がある |
| `power --metric relative-diff` | 相対変化の標準偏差、または `baseline > 0` の値を `--pilot` 用に相対変化へ変換したデータが必要 | 比例単位の計画が必要になる |
| 変化したサブセットだけの効果 | 結果を見てから対象を選ぶと、抽出・ペア化・主張の意味が変わる | 実例と事前に宣言できる仕様がある |
| 対数比（log-ratio）メトリクス | 単位が異なり、両値の正値制約もある | 既に対数比で主張する用途がある |
| 数値メトリクスのクラスターブートストラップ | ペア化、クラスター数、退化、再標本化単位の契約が必要 | 相関データで、行単位の再標本化より被覆率が改善する証拠がある |

数値クラスタリングに着手する場合の順序は、`mean-diff`、`relative-diff`、`quantile-diff`、
`sign-test` とします。

## 二項メトリクスとElo

| 候補 | 保留理由 | 着手条件 |
|---|---|---|
| Wilson連続性補正 | 共有する二項処理を変える一方、実測上の利点が未確認 | 権威ある数式とexact・Jeffreysとの較正比較がある |
| Normalized-Elo pentanomialまたはSiegmund補正 | 正しさの修正ではなく精緻化 | 引き分け率、ペア化、離散境界で実用上の差がある |
| 引き分けを考慮したElo検出力 | 現在の二項計画は引き分けをモデル化しない | 引き分け率を宣言でき、計画誤差が問題になる用途がある |

## `matrix` と計画

| 候補 | 保留理由 | 着手条件 |
|---|---|---|
| `matrix` 全体の判定 | 「最良」「差がある」「全候補を上回る」は別の主張 | 主張と多重性規則を宣言できる |
| `matrix` の失敗方針 | 失敗を常に片側の責任にはできない | 責任と両側失敗の扱いを定義できる |
| ブートストラップ・クラスター区間の補正 | 各行を独立とみなして補正すると、再標本化単位を誤る | 実際の再標本化単位で一群誤り率を保証できる |
| 予算制約付き割り当て | 不確かなペアの順位付けだけでは、予算配分の目的関数にならない | 目的関数と検証済みの割り当て法がある |

## 来歴と時間価値付き検定

| 候補 | 保留理由 | 着手条件 |
|---|---|---|
| 来歴グラフ・データベース | `verify-run` は値を解釈せず照合する来歴・ハッシュ項目を保持するが、関係はたどらない | 実験基盤へ拡張せず、実行間の関係を検証する汎用要件がある |
| 三項・五項の時間方策 | 3値・5値の結果に対する状態空間、e-process、報酬の意味が未定義 | 具体的な時間価値用途と較正試験がある |
| 複合仮説・オンライン対立仮説 | 同じ列からの `p1` 推定は妥当性を変える | 混合分布または信頼列の構成がある |
| Eloオプション・方策プリセット | 変換だけでは引き分けを扱えず、用途別方策はコア外 | 汎用化できる改良の利用実績がある |

## スコープ外

[プロダクトの目的と範囲](product-scope_ja.md#外部ツールが担う領域)に定めた対象外項目と一方向の依存は、
このマップの全候補にも適用します。外部ツールは共通形式の観測を出力し、`veridict` に判定を委ねられます。
