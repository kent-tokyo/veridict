# プロダクトの目的と範囲

[English](product-scope.md) | 日本語

`veridict` は、外部で集めた評価結果から、候補が基準に対して事前に定めた採用条件を満たすか判定する、
独立したRustライブラリとCLIです。`pass`、`fail`、`inconclusive` とともに、効果量、不確実性、
判定の前提、実行上の失敗を報告します。実際に候補を採用する操作は呼び出し側が担います。

この文書は開発方針と機能の範囲を定めます。現在の挙動と制約は[メトリクス・リファレンス](metrics_ja.md)
を参照してください。ここに記す製品目標は、現実装がすべて達成済みであることを意味しません。

中心となる用途は、変更した実装、モデル、アルゴリズム、設定を採用してよいか、再現可能な形で判断する
ことです。対応スコア、勝敗、実行上の失敗を、固定標本または宣言済みの逐次規則で評価します。入力と
設定まで追跡でき、証拠を追加する理由が分かり、CIへ組み込めることを重視します。手法の数は評価基準に
しません。

## 評価結果から判定までを受け持つ

| 責任 | veridictで扱う内容 |
|---|---|
| 評価結果の入力 | JSONL/CSVの読込、スキーマ検証、スコア・勝敗・ステータスの明示的な契約 |
| 証拠の構造 | ペアとクラスターの意味、独立した観測単位、順序と完了性の検査 |
| 統計判定 | 固定標本の区間としきい値、仮説と停止規則を宣言した逐次検定 |
| 実行上の失敗 | `timeout`・`crash`・`invalid`の件数、失敗方針、妥当性上限 |
| 説明と再現性 | 安定したJSON、Markdown要約、乱数シード、前提、判定時点の情報、渡された識別子 |
| 判断を支える分析 | 必要証拠量の見積もり、候補間の記述的比較、証拠を追加する比較の提案 |

判定の中心は `compare` と `sprt` です。`verify-run` は、渡された実行記録の構造と宣言された識別子を
検査します。成果物の真正性や、実行器が設定を守った事実までは証明しません。`power`、`matrix`、
`plan` は採用判断を支える機能です。実験的な `time-sensitive` は文書化したモデルの範囲にとどめ、
実験全体の制御へ範囲を広げる理由にはしません。

## 汎用的な契約と一方向の依存

機能は、試行、ペア、スコア、勝敗、ステータス、仮説、内容を解釈せず照合する識別子で仕様化します。
ペア化した勝敗、引き分け、Elo、逐次停止は、前提を明示できる場合に対象とします。

利用側は自分のメトリクスと観測記録を生成し、ライブラリまたはCLIへ渡します。用途別の変換処理、
実行器の設定、モデルへのアクセス、採用後の操作は利用側に置きます。依存方向は常に次のとおりです。

```text
外部の評価ツール -> veridict
```

利用側のソース、成果物、サービス、認証情報がなくても、`veridict` 単独でビルド・テスト・実行できる
必要があります。公開文書には再利用できる契約だけを記し、非公開の利用先名や優先順位の背景は含めません。
既存のシリアライズ項目名は、スキーマ変更を別途明示しない限り維持します。

## 正しい判定を手法の追加より優先する

1. 誤った `pass`、非有限な計算結果、不正な設定の受け入れ、過度に狭い不確実性の報告を先に直します。
   小標本や再標本化分布が一点に潰れる条件は、境界事例と誤判定率の検証を伴う判定仕様が必要です。
2. ペア比較と逐次判定の信頼性を高めます。実際の観測単位、最初の有効な停止時点、失敗の扱い、
   渡された実行記録の整合性を保ちます。
3. これらの用途で再現性、組み込みやすさ、説明、性能を改善します。改善は入力・設定・版を揃えて測ります。
4. 新しい統計手法は、具体的な判断上の必要性、定義された前提、校正結果、保守可能なAPIが揃った場合に
   追加します。[リサーチマップ](research-map_ja.md)は候補の記録であり、実装を約束するものではありません。

必要な証拠量は手法とデータ構造で変わります。一律の標本数制限では、判定の根拠を保証できません。

## 外部ツールが担う領域

コアでは、ベンチマークや対戦の実行、用途固有のプロトコル、モデル学習、用途固有のメトリクス生成、
LLMによる採点を扱いません。実験データベース、ダッシュボード、クラウドサービス、分散実行、成果物の
配備、適応的な実験制御も対象外です。結果を見て都合のよいしきい値を選ぶ機能や、評価条件の外まで
含めた一般的な優越性の認定も扱いません。

外部ツールはこれらを実行し、共通形式の観測を `veridict` へ渡せます。機能は、評価結果から判定までの
契約を改善し、外部ツールの責任を引き受けない場合に限って追加します。
